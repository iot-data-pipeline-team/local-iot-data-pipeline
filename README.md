# Real-Time Industrial IoT Data Pipeline

## Overview

This project is a real-time Industrial IoT data engineering platform that simulates an industrial environment where **machines and workers continuously generate operational and safety events**.

The generated events are published to **Apache Kafka**, processed in real time using **Apache Spark Structured Streaming**, and transformed through a **Medallion Architecture** consisting of Bronze, Silver, and Gold layers.

The project is designed to demonstrate a modern real-time data engineering workflow, including:

- Real-time event generation
- Distributed event streaming with Apache Kafka
- Stream processing with Apache Spark
- Data validation and transformation
- Business-rule enrichment
- Real-time aggregations
- Machine monitoring KPIs
- Worker safety monitoring KPIs
- Fault and anomaly simulation
- Event-time processing
- Watermarking
- Streaming checkpoints
- Containerized infrastructure using Docker

The project is being developed incrementally, with orchestration and downstream data loading planned as future stages.

---

# Project Goals

The main objectives of this project are to build and demonstrate an end-to-end real-time IoT data pipeline capable of:

- Simulating realistic industrial machine data
- Simulating industrial worker safety data
- Streaming events through Apache Kafka
- Processing events continuously using Apache Spark Structured Streaming
- Handling malformed and abnormal events
- Enriching raw events with business logic
- Producing analytical datasets from streaming data
- Calculating operational and safety KPIs
- Applying Medallion Architecture principles
- Building a foundation for future orchestration and data warehousing

The project also serves as a practical demonstration of modern **Data Engineering**, **Big Data**, and **Streaming Architecture** concepts.

# Pipeline Stages

## 1. Data Generation

The first stage simulates events generated by an industrial environment.

The project currently contains two independent producers:

- Machine Producer
- Worker Producer

Each producer continuously generates JSON events and publishes them to its corresponding Kafka topic.

The generators intentionally include realistic variations and occasional abnormal values to simulate real-world IoT data quality issues.

Examples include:

- Sensor fluctuations
- Machine faults
- Worker fatigue
- Unsafe worker behavior
- Missing timestamps
- Invalid values
- Missing identifiers
- Abnormal movement states

This makes the pipeline more representative of real industrial streaming systems.

# 4. Apache Kafka

Apache Kafka acts as the central event streaming platform.

The Kafka layer receives events generated by the machine and worker producers and makes them available to downstream streaming applications.

The current architecture uses a 3-broker Kafka KRaft cluster running through Docker Compose.

```text
Machine Producer ──────► sensor-events ───┐
                                         │
                                         ▼
                                   Kafka Cluster
                                         │
Worker Producer ───────► worker-events ───┘
                                         │
                                         ▼
                                  Spark Streaming
```

Kafka provides the foundation for:

- Event streaming
- Decoupling producers and consumers
- Distributed processing
- Fault tolerance
- Event buffering
- Scalable data ingestion

Detailed Kafka documentation will be provided separately.

---

# 5. Spark Structured Streaming

Apache Spark Structured Streaming is responsible for processing the Kafka events.

Spark continuously reads events from Kafka, parses the JSON messages, validates the data, applies transformations, and produces analytical datasets.

The general processing flow is:

```text
Kafka
  │
  ▼
Read Streaming Data
  │
  ▼
Parse JSON
  │
  ▼
Apply Schema
  │
  ▼
Validate Events
  │
  ▼
Transform & Enrich
  │
  ▼
Aggregate
  │
  ▼
Bronze / Silver / Gold
```

Spark Structured Streaming provides capabilities such as:

- Continuous event processing
- Event-time processing
- Watermarking
- Windowed aggregations
- Streaming checkpoints
- Fault recovery
- Scalable distributed processing

# Medallion Architecture

The project follows the **Medallion Architecture** pattern.

```text
              ┌───────────────────┐
              │      BRONZE       │
              │                   │
              │    Raw Events     │
              └─────────┬─────────┘
                        │
                        ▼
              ┌───────────────────┐
              │      SILVER       │
              │                   │
              │ Cleaned &         │
              │ Enriched Events   │
              └─────────┬─────────┘
                        │
                        ▼
              ┌───────────────────┐
              │       GOLD        │
              │                   │
              │ Business KPIs     │
              │ Aggregations      │
              └───────────────────┘
```

### Bronze

Raw and minimally processed data.

### Silver

Cleaned, validated, transformed, and enriched data.

### Gold

Business-ready aggregations and KPIs.

This architecture separates the different levels of data processing and makes the pipeline easier to maintain and extend.

---

# 6. Bronze Layer

The Bronze layer represents the raw ingestion layer.

Its purpose is to preserve the incoming streaming data with minimal transformation.

The Bronze layer acts as the foundation for downstream processing.

Typical responsibilities include:

- Receiving events from Kafka
- Applying the initial schema
- Parsing incoming JSON
- Preserving raw event information
- Handling malformed records
- Providing a reliable starting point for further processing

Conceptually:

```text
Kafka
  │
  ▼
Raw Events
  │
  ▼
Bronze Layer
```

The detailed Bronze implementation will be documented separately.

---

# 7. Silver Layer

The Silver layer contains cleaned, transformed, and enriched events.

At this stage, raw sensor information is converted into more meaningful business information.

Examples of Silver transformations include:

### Temperature Classification

```text
Critical → temperature > threshold
Warning  → temperature > threshold
Normal   → otherwise
```

### Vibration Classification

```text
Critical → vibration > threshold
Warning  → vibration > threshold
Normal   → otherwise
```

### Fault Processing

Machine fault information is converted into analytical flags that can be used by downstream aggregations.

### Time Attributes

Timestamp information can be used to derive:

- Event date
- Event hour
- Shift
- Time bucket

### Health and Risk Metrics

The Silver layer can also calculate derived operational metrics such as:

- Machine health score
- Risk score
- Uptime flag
- Fault indicators

Conceptually:

```text
Bronze
  │
  ▼
Validation
  │
  ▼
Transformation
  │
  ▼
Business Rules
  │
  ▼
Silver
```

---

# 8. Gold Layer

The Gold layer contains business-ready analytical datasets and KPIs.

Instead of individual raw events, the Gold layer focuses on aggregated information that can be used for monitoring and analysis.

Current analytical aggregations include:

- Machine Summary
- Hourly Summary
- Shift Summary

The project is also being extended to support worker-related analytics.

# Streaming Checkpoints

Spark Structured Streaming uses checkpoints to maintain streaming state and support recovery.

Conceptually:

```text
checkpoints/
│
├── bronze/
├── silver/
├── machine_summary/
├── hourly_summary/
└── shift_summary/
```

Checkpoints allow Spark to maintain information about streaming progress and state.

They are important for:

- Fault tolerance
- Stream recovery
- Stateful processing
- Windowed aggregations
